# وكيل · WAKIL

**موظف مالي محادثي، وليس فورم إنشاء فاتورة.**

ابدأ بطلب طبيعي: «راجع المديونيات، قارن بسياسة التحصيل، واحسب الأولويات». يفتح وكيل جلسة محفوظة، يسترجع السياق، يطلب خطة متعددة الخطوات من النموذج المتصل، وينفذ أدوات القراءة والحساب، ثم يراجع الأدلة ويضيف خطوات عند ظهور فجوات ضمن ميزانية محددة. النشاط الظاهر صادر عن التنفيذ الفعلي؛ أي كتابة محاسبية تحتاج مراجعة بشرية منفصلة.

> **نسخة تشغيل محلية للتطوير، لا تعتمدها لبيانات مالية حساسة أو إنتاج مؤسسي.** موصل النموذج وOdoo حقيقيان في الكود، لكن لم يُختبرا باتصالات حية في هذه البيئة. لا توجد مفاتيح مُعدّة؛ الشبكة هنا مقيّدة. عند غياب الاتصال، يُحفظ الطلب ويتوقف بوضوح، بلا ذكاء أو بيانات ERP وهمية.

## تشغيل سريع

Node.js **22.13+** وBun:

```bash
bun install --frozen-lockfile --ignore-scripts
npx prisma generate
npm run dev
```

افتح `http://localhost:3000`:

1. اكتب المطلوب مباشرة؛ تنشأ جلسة تلقائيًا.
2. من **الاتصالات**، أدخل عنوان OpenAI-compatible، ومعرّف النموذج ومفتاح API. الاختبار فعلي وقد يستهلك رصيد المزوّد. أدخل المفاتيح في النموذج المخصص، لا في المحادثة.
3. اربط Odoo بعنوان HTTPS وقاعدة البيانات والمستخدم ومفتاحه ورقم الشركة. استخدم بيئة اختبارية وصلاحيات محدودة أولًا. التطبيق يستهدف **Odoo 19 JSON-RPC**؛ يلزم إتاحة API والموديلات في باقتك.
4. أضف السياسات والمستندات من **الذاكرة والمستندات** أو زر الإرفاق، ثم ارجع لطلبك واضغط **استئناف**.

خادم التطبيق يحتاج اتصالًا صادرًا بالمزوّدين. موصل الشبكة يقبل HTTPS العام على 443 فقط، يثبت عنوان DNS عند فتح الاتصال، ويرفض الشبكات الخاصة والتحويلات. دعم Odoo داخلي عبر VPN/PrivateLink ليس ضمن هذه النسخة.

## ما يعمل الآن

| المجال | السلوك |
|---|---|
| جلسات محادثية | طلب حر، عنوان من الخطة، متابعة وسياق آخر 6 أدوار، سجل واستعادة وتصدير JSON |
| تخطيط | خطة موثقة بمخطط Zod، حتى 10 خطوات مرتبة بتبعيات، أسئلة توضيحية، أدوات محددة فقط |
| الذاكرة | سياسات ومستندات صريحة، بحث كلمات عربي، فهرس ملفات للنموذج، قراءة المصدر وبصمة SHA-256؛ ليست embeddings أو تعلمًا تلقائيًا |
| المستندات | TXT / MD / CSV / JSON نصي؛ رفع المتصفح حتى 64KB. لا استخراج PDF/صور أو OCR |
| الحساب | BigInt حتى منزلتين، جمع/طرح/ضرب/قسمة/نسبة تغير، أعمار مديونيات، تجميع CSV أو صفوف Odoo حسب المجموعة والعملة |
| Odoo | فواتير العملاء المفتوحة، فواتير الموردين المفتوحة، الفواتير/الإشعارات، بنود القيود المرحلة، الحسابات، دفاتر اليومية، معاملات البنك |
| الكتابة | تجهيز **مسودة قيد يومية فقط** → اعتماد الإجراء المحدد → محاولة واحدة → قراءة تحقق. لا ترحيل/دفع/حذف/تعديل تلقائي |
| النشاط | NDJSON مباشر، حالة كل خطوة وأدلتها، حركات مرتبطة بالنشاط وreduced-motion |
| الاستعادة | إعادة استخدام الخطوات المكتملة؛ استئناف يدوي للقراءة والتقرير؛ النتيجة غير المؤكدة للكتابة لا تعاد تلقائيًا |
| الوصول | RTL، موبايل، لوحة مفاتيح، focus trap، تباين واختبارات axe |

### حدود مالية مهمة

- الأموال حتى منزلتين عشريتين؛ لا ندّعي دعم دقة كل العملات.
- `receivables` و`payables` تعرضان المستندات المفتوحة، **وليستا صافي حساب المدينين/الدائنين** بعد إشعارات الخصم والدفعات غير المخصصة. الموصل يعيد هذا النطاق صراحة.
- قراءة Odoo حتى 200 سجل للخطوة، مع العدد الإجمالي وعلامة `truncated`. لا تُعامل العينة باعتبارها كامل دفتر الأستاذ.
- قيم debit/credit/balance في عملة الشركة، وamount_currency في عملة المعاملة؛ أداة التجميع تمنع خلط الاثنين.
- التقرير صياغة نموذجية مقيدة بالمصادر، لكنه ليس تدقيقًا ماليًا أو شهادة صحة أو امتثال ضريبي. يلزم مراجعته مهنيًا.
- لا توجد ضمانات exactly-once عبر Odoo، ولا مصالحة آلية لكتابة مجهولة. ابحث يدويًا بالمرجع `WAKIL:<approvalId>` ولا تعاود الإنشاء.

## جداول العمل والفحص — بدون انتظار ربط الذكاء

من القائمة اختر **جداول العمل والفحص**. ارفع CSV أو أنشئه من بياناتك، ثم راجع ربط الأعمدة وشغّل:

- **فحص القيود:** توازن كل قيد حسب العملة، ميزان الحسابات من الصفوف الصالحة، سطور غير صالحة وتكرارات محتملة. التوازن وحده لا يثبت صحة الحساب أو الشركة أو المعالجة.
- **مطابقة مصدرين:** مرجع حرفي بعد Unicode/trim، مبلغ موقّع وعملة متساويان، ومطابقة فريدة فقط. المكرر والناقص يظلان للمراجعة، ولا كتابة تسوية في ERP.
- **الفعلي والموازنة:** فرق ونسبة لكل بند وعملة، مع اختيار مصروفات/إيرادات. الموازنة الصفرية لا تُنتج نسبة مختلقة. يلزم أن يكون كل صف مساهمة مستقلة، لا موازنة فترة مكررة.

تُحفظ ورقة العمل مع بصمات المصادر وإصدار المحرك. يُعاد استخدام نفس الورقة لنفس المدخلات والمصادر. التصدير CSV لورقة الفحص **محدود بالجداول المعروضة: أول 100 نتيجة لكل قسم**، مع إجماليات وعدّادات لكامل المصدر؛ ليس تصديرًا كاملًا لدفتر الأستاذ. حماية من formula injection ومن إسقاط الأصفار الأولى/دقة الأرقام الطويلة. XLSX/PDF/OCR ليست مدعومة بعد.

يمكن للنموذج استخدام هذه الأدوات نفسها من المحادثة: `sheet.profile` ثم اختيار الأعمدة المرصودة في مراجعة لاحقة. `memory.search` يبحث أيضًا في أسماء ومصادر أوراق العمل؛ `memory.workpaper` يسترجع تحليلًا تاريخيًا مع تاريخ ومصادره، لا باعتباره بيانات ERP جديدة.

### دورة التخطيط التكيفية

تخطيط → أدوات → مراجعة أدلة → استكمال أو سؤال → تقرير. حتى **10 خطوات إجمالًا و3 مراجعات ناجحة**، ولا أكثر من جولتي توسع. لا تعديل لنتيجة خطوة مكتملة أو تجاوز بوابة الموافقة. الخطة ومراجعاتها محفوظة؛ فشل التقرير لا يعيد الحساب أو مراجعة ناجحة سابقة. النموذج المراجع من نفس المزوّد؛ **ليس تدقيقًا مستقلًا أو إثبات تفوق على محاسب بشري**.

## المسارات

- `/`: الموظف المالي المحادثي الجديد.
- `/lab`: مساحة الفاتورة التجريبية السابقة، محفوظة لاختبارات الموثوقية فقط؛ ERP محاكى.
- `/demo/invoice`: مختبر تقني لحقن الأعطال؛ ليس المنتج الأساسي.
- `/console`: واجهة قديمة مستقلة تحتاج Prisma ومزوّديها؛ لا تشترك تلقائيًا في جلسات الموظف الجديد.

## البيانات والتشغيل

```bash
npm run build
npm start
# قرص دائم، خارج .next:
WAKEEL_FINANCE_DB=/persistent-volume/wakil/finance.sqlite npm start
```

- افتراضيًا `data/finance.sqlite`، أو `finance.sqlite` بجوار `WAKEEL_RUNTIME_DB`. قاعدة المختبر منفصلة.
- أسرار الاتصال مشفرة AES-256-GCM بمفتاح `finance.sqlite.key` وصلاحية 0600. **المستندات والجلسات نفسها غير مشفرة في قاعدة SQLite**.
- مساحة المتصفح لها bearer token عشوائي، محفوظ في localStorage؛ الخادم يحتفظ ببصمته فقط. هذا ليس حساب مستخدم أو RBAC أو هوية موظف. فقد تخزين المتصفح يفقد طريق الوصول؛ لا توجد استعادة حساب.
- احمِ القرص وملف المفتاح. انسخ SQLite بطريقة متسقة مع WAL، واحتفظ بمفتاح التشفير معه في مخزن نسخ آمن. لا تضع أيًا منهما في Git.
- **عملية Node واحدة فقط**. الأقفال داخل العملية، لا leases موزعة أو workers أو orchestration engine. التنفيذ مرتبط بطلب HTTP بمهلة 170 ثانية، والاتصال الخارجي حتى 60 ثانية؛ عند الانقطاع تُحفظ الحالة للاستئناف، لا استمرار خلفي مضمون.
- مرجع اليوم `Africa/Cairo` افتراضيًا؛ يمكن تخصيص `WAKEEL_TIMEZONE` باسم IANA صالح.
- حدود أولية: 100 مستند و500 جلسة للمساحة، 40 طلبًا للجلسة، 10 خطوات للخطة، وحماية لحجم الأدلة. ليست سياسة retention أو quotas مؤسسية مكتملة.

## API الموظف

كل المسارات تحت `/api/finance`. `bootstrap` فقط ينشئ مساحة بلا bearer؛ بقية المسارات تتطلب `Authorization: Bearer <workspace-token>`:

| المسار | الوظيفة |
|---|---|
| `POST /bootstrap` | إنشاء مساحة ومفتاح وصول عشوائي |
| `GET /status` | الجلسات وفهرس المستندات وحالة الاتصالات؛ بلا أسرار |
| `POST /sessions` | إنشاء جلسة |
| `GET /sessions/:id` | الجلسة والخطوات والموافقات |
| `POST /sessions/:id/run` | رسالة/استئناف بمعرّف طلب؛ NDJSON لتحديثات التنفيذ |
| `GET/POST /documents` | الفهرس أو إضافة مستند/سياسة |
| `GET/DELETE /documents/:id` | مراجعة/حذف مصدر |
| `GET/POST /connections` | حالة الاتصالات أو اختبار إعدادات جديدة ثم حفظها مشفرة |
| `DELETE /connections/:kind` | إزالة اتصال |
| `POST /sheets` | إنشاء جدول CSV؛ ملف التعريف عبر `GET /sheets/:documentId` |
| `GET/POST /workpapers` | سجل أوراق العمل أو تشغيل تحليل وحفظه |
| `GET /workpapers/:id` | نتيجة محفوظة ومصادرها؛ تصدير عبر `/:id/export` |
| `POST /approvals/:id` | اعتماد/رفض ببصمة الإجراء المحدد |

معرّف الطلب يمنع تكرار الدور نفسه داخل الجلسة؛ لا يمنع المستخدم من تقديم طلب جديد مماثل تجاريًا. طلب اعتماد جديد ليس dedup تلقائيًا لإجراء سابق.

## التحقق

```bash
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

- `tests/finance`: تخطيط وتنفيذ متعدد الخطوات بمزوّدين **محقونين للاختبار**، ذاكرة وعزل وتشفير، تجميع عشري وعملات، Odoo scoped reads، موافقات وتزامن ونتيجة مجهولة. ليست أدلة اتصال حي.
- `tests/browser/finance.spec.ts`: الترحيب → طلب → توقف صريح دون نموذج → استعادة → إعدادات، ذاكرة وملفات وموبايل وفحوص وصول.
- اختبارات المختبر القديم محفوظة على `/lab`؛ لا تعني نجاح الموصل الحي الجديد.
- تعريف GitHub Actions موجود؛ لا نفترض أن CI البعيد نجح قبل ظهوره فعلًا.

في البيئة المقيدة وُلد عميل Prisma بـ `--no-engine` لفحص الأنواع والبناء فقط؛ هذا لا يثبت تشغيل قاعدة الواجهة القديمة. المحرك المالي الجديد يستخدم SQLite ولا يحتاج Prisma.
